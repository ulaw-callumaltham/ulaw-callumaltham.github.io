Tutorial

Employers want to see what you can do, not just what you say you can do. The projects section is where you provide that evidence, and it will grow throughout your course. In this lesson you will build it using one of the most common patterns on the web: the card.


What Is a Card?

A card is a box that groups everything about one item: a heading, a short description and some extra details. You have seen them everywhere: product listings, news articles, streaming services. They work well for projects because each one is self-contained and easy to scan.

<article class="card">
    <h3>Portfolio Website</h3>
    <p>The website you are looking at, built during induction week.</p>
    <p class="tech">HTML, CSS</p>
</article>

<article> is a semantic element for a self-contained piece of content that would still make sense on its own. Each project card fits that description. Notice the heading is an <h3>, because it sits inside the Projects section's <h2>.


Repeating a Pattern

All three cards use exactly the same HTML structure and the same classes; only the text changes. This is the real power of classes: you write the CSS once, and every element with that class is styled the same way. To add a fourth project later, you copy a card and change its text, and it is styled automatically.


Arranging Cards in a Grid

To place the cards side by side, they are wrapped in a container and styled with CSS Grid:

.card-grid {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
    gap: 20px;
}

The second line looks complicated, but it reads as: "create as many columns as will fit, each at least 220 pixels wide, and share any spare space equally between them" (1fr means one fraction of the available space). The result is a responsive layout: three columns on a laptop, two on a tablet and one on a phone, with no extra code.

Most visitors to your portfolio, including recruiters, will be looking on their phone, so layouts that adapt to the screen size are essential.


Making a Card Look Like a Card

A white background, padding, rounded corners and a subtle box-shadow lift the card off the page. The shadow value 0 2px 8px rgba(0, 0, 0, 0.1) means: no horizontal offset, 2 pixels down, 8 pixels of blur, in black at 10% opacity.


What If I Don't Have Projects Yet?

That is completely normal at the start of a course. Your portfolio website is itself your first project, and you may have built something in the Python session. For the rest, add a "Coming Soon" card naming the module the project will come from. As the year goes on, you will replace these with real work.


Your Task

  1. The first card is done for you. Add two more <article class="card"> elements inside the card-grid div.
  2. Give each one an <h3>, a description and a tech paragraph.
  3. Complete the .card-grid, .card, .card h3 and .tech rules in the CSS tab.
  4. Make the preview narrower or wider (if your screen allows) and watch the cards rearrange.

Extension Tasks

  • Add a link at the bottom of each card, e.g. View on GitHub, using what you learnt in Lesson 3.
  • Make cards react when the mouse is over them with a .card:hover rule, e.g. a stronger shadow. :hover is a pseudo-class, which selects an element only while it is in a particular state.

Recap

  • A card groups everything about one item; article is a good semantic element for it.
  • Classes let you style many elements with one rule.
  • CSS Grid with repeat(auto-fit, minmax(...)) creates a responsive layout.
