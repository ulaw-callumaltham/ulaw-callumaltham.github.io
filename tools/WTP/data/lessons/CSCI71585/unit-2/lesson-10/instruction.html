Tutorial

Everything you have built so far sends information to the user. Forms work the other way: they collect information from the user. Logging in, searching, checking out and signing up are all forms. In this lesson you will learn how to build forms in HTML, how to label them so that everyone can use them, and how the browser can check what users enter.

The starter code contains a sign-up page for a student society, with an empty form. You will build the form one field at a time. As before, complete each Try It section in the editor before moving on.


How Forms Work

A form is a group of controls, such as text boxes, checkboxes and buttons, wrapped in a <form> element. When the user submits the form, the browser collects the value of each control and sends them to a web server, which processes them, for example by saving a new account to a database.

<form action="/signup" method="post">
    <!-- form controls go here -->
</form>
  • action is the URL the data is sent to.
  • method is how it is sent. get adds the data to the end of the URL, which suits searches. post sends it hidden inside the request, which suits anything that changes data or contains personal information.

The server side of forms is covered later in the module. In this lesson you will focus on building the form itself in HTML.

ℹ️ Info: The forms in this platform are not connected to a server. Instead, when you submit a form, the platform shows you the data that would have been sent. This is a useful way to check your form is working.

Text Inputs and Labels

Most form controls use the <input> element, which is a void element. Every control needs a label: the text that tells the user what to enter. Labels are written with the <label> element, and connected to their control by matching the label's for attribute to the control's id:

<label for="full-name">Full name</label>
<input type="text" id="full-name" name="full-name">

Connecting the label properly has two important effects:

  • Screen readers read out the label when the user reaches the control. Without it, they just announce "edit text", and the user has to guess what to type.
  • Clicking the label moves the cursor into its control. This gives everyone a larger target to click, which especially helps users with limited motor control, and is essential for small controls like checkboxes.

The name attribute is different from the id. The id connects the control to its label, while the name labels the data when it is sent to the server, such as full-name=Sam Patel. A control without a name is not sent at all. It is common, and perfectly fine, for the two to have the same value.

⚠️ Warning: The placeholder attribute shows hint text inside an empty control, such as placeholder="e.g. Sam Patel". It is not a replacement for a label: it disappears as soon as the user starts typing, so they can no longer check what the field was for, and it is often too faint to read. Use it only for an example of the expected format, alongside a proper label.

Try It

  1. Inside the <form>, add a label and a text input for Full name, using full-name for the id, name and the label's for.
  2. Click the label text in the preview and check that the cursor moves into the text box.

Input Types

The type attribute changes what kind of data an <input> accepts. Choosing the right type matters: on phones, it brings up the right keyboard, and the browser can check the format of what is entered.

  • type="text": any single line of text. This is the default.
  • type="email": an email address. The browser checks it contains an @, and phones show a keyboard with an @ key.
  • type="password": hides what is typed behind dots.
  • type="number": numbers only, with arrows to increase or decrease the value.
  • type="tel": a phone number. Phones show a number keypad.
  • type="date": a date, with a date picker.
  • type="checkbox" and type="radio": for choosing options, covered below.
💡 Tip: Wrapping each label and control in its own <p> or <div> puts each one on its own line. Without this, the inputs are inline elements, so they sit side by side. In the next unit, you will lay out forms properly with CSS.

Try It

  1. Wrap your full name label and input together in a <p>.
  2. Below it, in its own <p>, add a label and input for Email address with a type of email, using email for the id and name.
  3. Add a placeholder to the email input showing an example address, such as e.g. sam@example.com.

Checking Input

The browser can check what users enter before the form is submitted, using attributes on each control:

  • required is a Boolean attribute: the form cannot be submitted until the control has a value.
  • minlength and maxlength set the shortest and longest text allowed.
  • min and max set the smallest and largest value allowed for numbers and dates.
<label for="age">Age</label>
<input type="number" id="age" name="age" min="16" max="120" required>

If any check fails when the user submits, the browser stops the submission and shows a message next to the first problem.

⚠️ Warning: Checks in HTML are there to help users, not to protect your website. Anyone can turn them off or send data straight to the server without using your form at all. The server must always check every piece of data it receives again. This is a basic rule of web security that you will meet again later in the module.

Try It

  1. Make the full name and email inputs required.
  2. Add a <button> containing Sign up at the end of the form, just before </form>. You will learn about buttons properly at the end of this lesson.
  3. Click the button with both fields empty, and check that the browser shows a message.
  4. Type a name and an email address without an @, then click the button again. The browser shows a different message.

Dropdown Lists

A <select> element creates a dropdown list, with each choice in an <option> element. The value attribute is what is sent to the server; the text between the tags is what the user sees:

<label for="campus">Campus</label>
<select id="campus" name="campus">
    <option value="">Choose a campus</option>
    <option value="leeds">Leeds</option>
    <option value="london">London</option>
</select>

Notice the label connects to the <select> exactly as it does to an <input>. Giving the first option an empty value means that, if the <select> is required, the user must actively choose a real option.

Try It

  2. Add a first option of Choose your course with an empty value, followed by options for MSc Computing, MSc Cyber Security and Other, with values of computing, cyber and other.
  3. Make the <select> required.

Radio Buttons and Checkboxes

  • Radio buttons (type="radio") let the user choose exactly one option from a group.
  • Checkboxes (type="checkbox") let the user choose any number of options, including none.

Options in the same group share the same name. For radio buttons, this is what makes them a group: selecting one automatically deselects the others. Each option needs its own id for its label, and its own value to send to the server.

A group of options is wrapped in a <fieldset>, and the question that the group answers goes in a <legend>:

<fieldset>
    <legend>How would you like to be contacted?</legend>
    <input type="radio" id="contact-email" name="contact" value="email">
    <label for="contact-email">Email</label>
    <input type="radio" id="contact-phone" name="contact" value="phone">
    <label for="contact-phone">Phone</label>
</fieldset>

Screen readers announce the legend along with each option, such as "How would you like to be contacted? Email, radio button, 1 of 2", so the user knows what the options are for.

💡 Tip: For radio buttons and checkboxes, the label usually goes after the control, which is the convention users expect. For text inputs and dropdowns, the label goes before.

Multi-Line Text

For longer answers, use a <textarea>, which allows several lines of text. Unlike <input>, it has a closing tag. The rows attribute sets how many lines tall it is:

<label for="comments">Comments</label>
<textarea id="comments" name="comments" rows="4"></textarea>
⚠️ Warning: Any whitespace between <textarea> and </textarea> becomes part of its content, so the box will start with spaces or blank lines already in it. Always write the closing tag immediately after the opening one.

Try It

  1. After the checkboxes, in its own <p>, add a label and a textarea for Anything else we should know?, using message for the id and name, with 4 rows. It should not be required.

Buttons

The <button> element creates a button, with its text between the tags. Its type attribute controls what it does:

  • type="submit" submits the form. This is the default for a button inside a form.
  • type="reset" clears every control in the form back to its starting value.
  • type="button" does nothing on its own. It is used with JavaScript, which you will learn in a later unit, to make a button do something else, such as showing a hidden menu.
<button type="submit">Sign up</button>
💡 Tip: Always set the type of a button, even when it is submit. A button with no type inside a form submits it, which can cause surprising bugs when you meant it to do something else.
⚠️ Warning: Think carefully before adding a reset button. It is easy to click by mistake, and it wipes everything the user has typed, with no way to undo it. Most modern forms do not include one.
ℹ️ Info: You may also see <input type="submit" value="Sign up">. This is an older way to create a submit button. It still works, but <button> is more flexible, since it can contain other elements such as an icon.

Try It

  1. Add type="submit" to your Sign up button.
  2. Check the button is the last thing inside the form, after the textarea.
  3. Click every label in the preview, and check that each one selects or moves into its control.
  4. Fill in the whole form, tick two of the events, and click Sign up. Check the data the platform shows: each value should be listed against its name, and both events should appear under interests.

Check Your Page

Your form should contain, in this order:

  1. A required text input for full name.
  2. A required email input with a placeholder.
  3. A required dropdown for course, with an empty first option.
  4. A fieldset of two radio buttons for year, sharing the same name.
  5. A fieldset of three checkboxes for events, sharing the same name.
  6. An optional textarea.
  7. A submit button.

Your year fieldset should look like this:

<fieldset>
    <legend>Which year are you in?</legend>
    <input type="radio" id="year-1" name="year" value="1">
    <label for="year-1">First year</label>
    <input type="radio" id="year-2" name="year" value="2">
    <label for="year-2">Second year</label>
</fieldset>

Also check that every control has a label connected by matching for and id, every id is unique, and every control has a name.
