Tutorial

In the last lesson you used <div> elements to group content, and you saw that they say nothing about what that content is. HTML also has elements for grouping the major areas of a page, such as its header, navigation, main content and footer, which do describe what each area is. Using them is called semantic HTML, and it is one of the most important habits you can build as a web developer.

The starter code contains a blog page built entirely from <div> elements. Over this lesson you will rebuild it with semantic elements. As before, complete each Try It section in the editor before moving on.


What Is Semantic HTML?

Semantics means meaning. Semantic HTML means choosing each element for what the content is, rather than how it should look. You have been doing this since Lesson 2: choosing headings by their level in the outline, choosing <ol> when order matters, and choosing <strong> for important text rather than <b> for bold text.

Compare these two versions of the same page area:

<!-- Non-semantic -->
<div class="nav">
    ...
</div>

<!-- Semantic -->
<nav>
    ...
</nav>

Both look identical in the browser. But only the second tells the browser that this area is navigation. The class name nav means nothing to the browser; it is just a label for CSS.


Why It Matters

  • Accessibility: screen readers treat the main semantic areas as landmarks. A user can jump straight to the main content or the navigation, instead of listening to the whole page from the top. On a page of <div> elements, there are no landmarks to jump to.
  • Search engines: semantic elements help search engines work out which content is the important part of the page, and which is repeated navigation or footer content.
  • Other tools: features like a browser's reader mode use semantic elements to find the article content and strip away everything else.
  • Developers: </nav> is much easier to understand than the fifth </div> in a row, for other developers and for you, months later.
ℹ️ Info: In the UK, public sector websites are legally required to meet accessibility standards, and the Equality Act 2010 requires service providers, including private businesses, to make reasonable adjustments for disabled people. Semantic HTML is the foundation of an accessible website, and it costs nothing extra to write.

The Page Structure Elements

A typical page is built from these elements:

body
├── header       Site name, logo, and often the main navigation
│   └── nav      The main navigation links
├── main         The main content of this page
│   ├── article  A self-contained piece of content
│   │   └── section
│   └── aside    Related content, such as a sidebar
└── footer       Copyright, contact details and secondary links

header

<header> contains introductory content: usually the site name or logo, and often the main navigation. A page's main header sits at the top of the <body>. An <article> or <section> can also have its own header, containing its heading and details such as the author and date.

⚠️ Warning: Do not confuse <header> with <head> or with headings. <head> holds information about the page and is never displayed. <header> is a visible area of the page. Headings (<h1> to <h6>) are titles, which often go inside a header.

nav

<nav> contains a block of major navigation links, such as the site's main menu or a table of contents. Its links are usually written as a list. Not every group of links needs a <nav>: a few links in a paragraph or in the footer are fine without one.

main

<main> contains the content that is unique to this page, as opposed to the header, navigation and footer that repeat across every page of the site. There must be only one <main> on a page, and it must not go inside an <article>, <aside>, <header>, <footer> or <nav>.

footer

<footer> contains closing information: copyright notices, contact details and links to policies. Like <header>, it can be used for the whole page or within an <article>.

Try It

  1. In the starter code, replace <div class="header"> and its closing </div> with <header> and </header>.
  2. Replace <div class="nav"> with <nav>, <div class="main"> with <main>, and <div class="footer"> with <footer>, along with their closing tags.
  3. Each element still needs the matching closing tag, so take care to change the right </div>. The comments after each closing tag in the starter code will help.
  4. Remove the class attributes from the elements you have changed; the element names now say what each area is.
💡 Tip: Nothing in the preview will change. That is expected: semantic elements change what the page means, not how it looks.

Grouping the Main Content

article

<article> contains a piece of content that is self-contained: it would still make sense if it were taken out of the page and shown somewhere else on its own. Blog posts, news stories, product cards and forum posts are all articles. A page can contain several, such as a list of blog posts.

section

<section> groups content on a single theme, such as one chapter of a long article, or the "About" and "Contact" areas of a page. A section should almost always start with a heading; if you cannot think of a heading for it, it probably should not be a section.

aside

<aside> contains content that is related to the content around it, but not part of it: a sidebar, a "related posts" box, an author biography or a glossary of terms. If you removed it, the main content would still make complete sense.

💡 Tip: To choose between <article> and <section>, ask: "Would this make sense on its own, on a different website?" If yes, it is an article. If it only makes sense as part of this page, it is a section.

The time Element

Dates and times can be written in many ways, such as 3rd March, 03/03 or last Tuesday. The <time> element marks a date or time, and its datetime attribute gives it in a standard format that computers can read, while the text stays readable for people:

<time datetime="2026-10-12">12 October 2026</time>

The datetime format is year, month and day, separated by hyphens. Search engines, calendars and browser tools can then understand the date correctly.

Try It

  1. Inside <main>, replace <div class="post"> with <article>, since a blog post is self-contained.
  2. The post's title and date are wrapped in <div class="post-header">. Replace it with a <header>: this is the article's own header.
  3. Wrap the post's publication date in a <time> element with a datetime of 2026-10-12.
  4. The post is split into two parts, each wrapped in <div class="post-part"> and starting with an <h2>. Replace each one with a <section>.
  5. Replace <div class="sidebar"> with an <aside>, since the author biography is related to the post but not part of it.
  6. Remove the class attributes from the elements you have changed.

When No Semantic Element Fits

Semantic elements do not replace <div> completely. If you need to group content purely so you can style it, and none of the elements in this lesson describe it, a <div> is still the right choice. The goal is not to remove every <div>; it is to use a semantic element wherever one genuinely describes the content.

⚠️ Warning: Do not swap every <div> for a <section> just to make the page look more semantic. Using an element for the wrong meaning is as misleading as using no meaning at all.

Check Your Page

Your finished page should have this structure, with no <div> elements left:

body
├── header
│   ├── p (site name)
│   └── nav
│       └── ul
├── main
│   ├── article
│   │   ├── header
│   │   │   ├── h1
│   │   │   └── p (containing time)
│   │   ├── p
│   │   ├── section
│   │   └── section
│   └── aside
└── footer

Also check that:

  • There is exactly one <main>.
  • Every opening tag has a matching closing tag of the same name.
  • The date is in a <time> element with a datetime attribute.
  • The preview looks the same as it did before you started.
