Tutorial

Timetables, price lists, league tables and results are all tabular data: information that makes sense arranged in rows and columns, where each value relates to both its row and its column. In this lesson you will learn how to build tables in HTML, and how to structure them so they make sense to everyone, including screen reader users.

The starter code contains a page for a five-a-side football league with its results written as plain text. You will turn them into a proper table. As before, complete each Try It section in the editor before moving on.


Building a Table

A table is built from four basic elements:

  • <table> wraps the whole table.
  • <tr> (table row) creates a row.
  • <td> (table data) creates a data cell inside a row.
  • <th> (table header) creates a header cell, which labels a row or column.

HTML tables are built row by row. You create a row, then fill it with cells from left to right, then create the next row:

<table>
    <tr>
        <th>Module</th>
        <th>Day</th>
        <th>Room</th>
    </tr>
    <tr>
        <td>Web Technologies</td>
        <td>Monday</td>
        <td>2.04</td>
    </tr>
    <tr>
        <td>Programming</td>
        <td>Wednesday</td>
        <td>1.12</td>
    </tr>
</table>

There are no column elements: columns are formed by the cells lining up underneath each other. That is why every row must contain the same number of cells. If one row has fewer cells, the columns no longer line up.

ℹ️ Info: Browsers display tables with no borders by default, so the preview will show your data in columns but without lines between the cells. Borders, spacing and colours are all added with CSS, which you will learn in the next unit.

Header Cells and Scope

A <th> cell does more than look bold. It tells the browser that the cell is a label for other cells. This matters for screen reader users: when they move through a table, the screen reader reads out the relevant headers with each cell, such as "Away, United", so they do not have to remember which column they are in.

Headers can label a column or a row. The scope attribute makes this explicit:

  • scope="col" means the header labels the column below it.
  • scope="row" means the header labels the row to its right.
<table>
    <tr>
        <th scope="col">Day</th>
        <th scope="col">Opening hours</th>
    </tr>
    <tr>
        <th scope="row">Monday</th>
        <td>9am to 5pm</td>
    </tr>
</table>

Here, the day names label each row, so they are row headers, while the top row labels the columns.

Try It

  1. Add scope="col" to each of the header cells in your results table.

Table Sections and Captions

Larger tables can be divided into sections that describe the role of each group of rows:

  • <thead> contains the header row or rows.
  • <tbody> contains the main data rows.
  • <tfoot> contains summary rows, such as totals. It is optional.

A table can also have a <caption>: a title that describes what the table shows. It must be the first element inside the <table>. Screen readers announce it before reading the table, so users can decide whether to read it or skip it.

<table>
    <caption>Library opening hours</caption>
    <thead>
        <tr>
            <th scope="col">Day</th>
            <th scope="col">Opening hours</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <th scope="row">Monday</th>
            <td>9am to 5pm</td>
        </tr>
        <tr>
            <th scope="row">Tuesday</th>
            <td>9am to 8pm</td>
        </tr>
    </tbody>
</table>

Try It

  1. Wrap the header row of your results table in <thead>, and the four result rows in <tbody>.
  2. Add a <caption> containing Week 1 results as the first element inside the table.

Row Headers

Many tables have headers both along the top and down the left-hand side. A league table is a good example: each row is about one team, so the team name labels the row.

Spanning Rows and Columns

A cell can stretch across more than one column or row:

  • colspan="2" makes a cell span two columns.
  • rowspan="2" makes a cell span two rows.
<tr>
    <th scope="row">Wednesday</th>
    <td colspan="2">Closed all day</td>
</tr>

When a cell spans columns, the row needs fewer cells, because one cell is taking up the space of several. The total width of each row must still add up to the same number of columns.

💡 Tip: Use spanning sparingly. Complex tables with many merged cells are hard to build correctly, and very hard to follow with a screen reader. If a table is getting complicated, consider splitting it into two simpler tables.

Tables Are for Data, Not Layout

Before CSS could arrange content into columns, developers used tables to lay out entire pages, putting the navigation in one cell and the content in another. You may still see this in very old websites and in HTML emails.

⚠️ Warning: Never use a table to position content on a page. Screen readers announce layout tables as data tables and read them cell by cell, which is confusing, and layout tables cannot adapt to different screen sizes. Only use a table when the content is genuinely tabular data. Page layout is done with CSS.

Check Your Page

Your results table should be structured like this, with all four results:

<table>
    <caption>Week 1 results</caption>
    <thead>
        <tr>
            <th scope="col">Home</th>
            <th scope="col">Score</th>
            <th scope="col">Away</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <td>Rovers</td>
            <td>3 - 1</td>
            <td>United</td>
        </tr>
        <!-- ...and three more rows -->
    </tbody>
</table>

Also check that:

  • Every row in each table has the same number of cells, and the columns line up in the preview.
  • Both tables have a caption, a <thead> and a <tbody>.
  • The team names in the league table are row headers.
  • The plain-text paragraphs of data have been removed.
