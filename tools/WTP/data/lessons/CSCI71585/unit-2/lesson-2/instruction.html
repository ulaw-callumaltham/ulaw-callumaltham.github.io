Tutorial

Most of what people read on the web is text, so most of the HTML you write will be marking up text. In this lesson you will learn how to structure text properly with headings and paragraphs, how the browser handles spaces and line breaks in your code, and how to display characters that HTML would otherwise treat as code.

The starter code contains a short article about the history of the web. Over this lesson you will turn it into a properly structured page. As before, complete each Try It section in the editor before moving on.


Headings

HTML has six levels of heading, from <h1> to <h6>:

<h1>Heading level 1</h1>
<h2>Heading level 2</h2>
<h3>Heading level 3</h3>
<h4>Heading level 4</h4>
<h5>Heading level 5</h5>
<h6>Heading level 6</h6>

The number is the heading's level of importance, not its size. Headings work like the contents page of a book:

  • <h1> is the title of the whole page. It is good practice to have only one.
  • <h2> headings mark the main sections of the page, like chapters.
  • <h3> headings mark sub-sections within an <h2> section, and so on down to <h6>.

Together, the headings form an outline of the page:

<h1>Visiting Leeds</h1>
    <h2>Getting There</h2>
        <h3>By Train</h3>
        <h3>By Car</h3>
    <h2>Places to Visit</h2>
        <h3>Museums</h3>
        <h3>Parks</h3>

The indentation here is only to show the outline; in a real page, each heading would have content beneath it.

⚠️ Warning: Do not skip heading levels. An <h3> should only come after an <h2>, never directly after an <h1>. Also never choose a heading because of its size: if you want text to look bigger, that is a job for CSS. Choose the level that matches the content's place in the outline.
ℹ️ Info: Headings matter for accessibility. Many screen reader users navigate a page by jumping from heading to heading, in the same way a sighted user skims a page by looking at the headings. A page with a clear heading outline is far easier to use without seeing it. Search engines also use headings to understand what a page is about.

Paragraphs

The <p> element marks a paragraph of text. Browsers display each paragraph as a separate block, with space above and below it.

People tend to skim web pages rather than read every word. Short paragraphs that each cover one idea are much easier to read on screen than long blocks of text.

💡 Tip: Do not use empty paragraphs (<p></p>) to add space between content. Spacing is part of how a page looks, so it is controlled with CSS. HTML should only describe what the content is.

Whitespace

Whitespace means spaces, tabs and line breaks. When the browser displays text, it collapses any run of whitespace into a single space. This means that:

  • Pressing Enter in your code does not start a new line on the page.
  • Typing several spaces in a row shows only one space on the page.
<p>This     text
   is spread
      over several lines.</p>

The browser displays this as a single line: This text is spread over several lines.

This is actually useful: it is the reason you can indent and space out your code to make it readable without changing what appears on the page.

  2. Undo those changes.

Line Breaks

Sometimes a line break is part of the content itself, such as in a postal address or a poem. For these, use the <br> element, which is a void element you met in Lesson 1.

<p>
    The University of Law<br>
    Leeds Campus<br>
    Leeds
</p>
⚠️ Warning: Only use <br> where the line break belongs to the content. Do not use it to separate paragraphs (use separate <p> elements) or to add space between elements (use CSS).

Try It

  1. At the bottom of the starter page is a paragraph containing an address, but it displays as one long line. Add <br> elements so that each part of the address appears on its own line.

Preformatted Text

The <pre> element is the exception to whitespace collapsing. Text inside <pre> (short for preformatted) is displayed exactly as you type it, with every space and line break kept. Browsers also display it in a monospace font, where every character is the same width, so text lines up in columns.

<pre>
Name      Score
Amira       92
Ben         87
</pre>

<pre> is commonly used for displaying code, and for text-based content where alignment matters.

Character Entities

Some characters have a special meaning in HTML. For example, the browser reads < as the start of a tag. So what happens if you want to write about the <p> element on your page?

<p>Every paragraph uses the <p> element.</p>

The browser treats <p> in the middle of the sentence as a real tag, so it disappears from the page. To display these characters as text, you use a character entity: a code that starts with & and ends with a semicolon.

<p>Every paragraph uses the &lt;p&gt; element.</p>

The most common entities are:

  • &lt; displays < (short for "less than")
  • &gt; displays > (short for "greater than")
  • &amp; displays & (short for "ampersand"). You need it because & itself starts an entity.
  • &quot; displays " (short for "quotation mark")
  • &copy; displays © (the copyright symbol)
  • &nbsp; is a non-breaking space. It never collapses, and a line never wraps at that point, so it keeps things like 10&nbsp;km together on one line.
ℹ️ Info: Because your pages use UTF-8 encoding (from Lesson 1), you can type most special characters directly, such as £, é or ©. You only need entities for characters that HTML would otherwise treat as code, mainly <, > and &.
💡 Tip: <pre> keeps whitespace, but it still reads tags. To display HTML code inside a <pre>, you still need &lt; and &gt;.
