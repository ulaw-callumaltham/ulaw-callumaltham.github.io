Tutorial

Congratulations on reaching the final lesson of this unit! You now know enough Python to build a complete, working game. In this lesson you will combine variables, input, comparisons, if statements, a while loop and a function into a number guessing game.

The computer picks a secret number between 1 and 100. The player keeps guessing, and after each guess the program says whether the guess was too high or too low. When the player finds the number, the program tells them how many attempts they took.


Importing a Module

To pick a random number, we need a tool that is not built into Python by default. Python comes with a large library of ready-made modules, each containing extra functions for a particular kind of job: maths, dates and times, files and much more. To use a module, you import it at the top of your file.

The random module contains functions for generating random numbers:

import random

secret = random.randint(1, 100)
print(secret)

random.randint(1, 100) means "use the randint function from the random module". It returns a random whole number between 1 and 100. Unlike range(), both ends are included here. Run this a few times and you will get a different number each time.


Plan Before You Code

Experienced programmers rarely start typing straight away. They first break the problem into small steps, written in plain English. This is called decomposition, and it turns a big, vague problem into a list of small problems you already know how to solve.

Here is a plan for the game, with the Python idea each step needs:

  1. Pick a random secret number. (the random module)
  2. Set the number of attempts to 0. (a variable)
  3. Repeat until the guess is correct: (a while loop)
    • Ask the player for a guess and convert it to an integer. (input() and int())
    • Add 1 to the attempts. (+=)
    • If the guess is too high or too low, tell the player. (if and elif)
  4. Congratulate the player and tell them how many attempts they took. (an f-string)

Every step uses something from an earlier lesson. If you get stuck on one part, go back to the lesson that covered it.


How the Starter Code Is Organised

The starter code puts the game inside a function called play_game() and calls it at the bottom. Wrapping the game in a function keeps it tidy and means you can easily run it again, which you will need for the "play again" extension.

Inside the function, secret, attempts and guess are already set up. guess starts at 0 for the same reason password started as an empty string in Lesson 8: the while condition is checked before the first guess, so the variable needs to exist already. Since the secret is never 0, the loop is guaranteed to run at least once.


Testing and Debugging

A game based on random numbers can be tricky to test, because you do not know the right answer. Two useful techniques:

  • Print the secret while testing. Add print(secret) near the top so you can check your logic, then remove it when the game works.
  • Build it up gradually. Get the loop working first, then add the hints, then the attempt counter. Run your code after each small change rather than writing everything and hoping it works.

Your Task

Complete the play_game() function in the starter code so the game works as planned above. A sample game might look like this:

I'm thinking of a number between 1 and 100.
Your guess: 50
Too high!
Your guess: 25
Too low!
Your guess: 37
Correct! You got it in 3 attempts.

A good strategy for the player is to guess the middle of the remaining range each time. This approach, called a binary search, guarantees you can find any number from 1 to 100 in at most 7 guesses. It is also an important algorithm you will meet again in computing.

Once your game works, move on to the Extension Challenge below and see how many levels you can complete.


Extension Challenge: Level Up Your Game

Finished already? Each level below adds one new feature to the same game, and each one is a little harder than the last. Work through them in order, and make sure your game still works after every level before moving on. It is a good idea to use the Download button to save a copy each time you complete a level, so you always have a working version to go back to.


Level 1: Getting Warmer

Make the hints more helpful. If the guess is within 5 of the secret number, add You're very close! to the hint.

New idea: abs() gives the distance between two numbers, ignoring whether it is positive or negative. abs(guess - secret) is 3 whether the guess is 3 above or 3 below.

Your guess: 40
Too low! You're very close!

Level 2: Limited Lives

Give the player a maximum of 7 attempts. Show how many they have left after each wrong guess. If they run out, reveal the secret number and end the game.

Think about: your while loop now has two reasons to stop. You can combine them with and in the condition, or use break. After the loop, how will you know whether the player won or ran out of attempts?

Too high! 4 attempts left.
...
Out of attempts! The number was 63.

Level 3: No Cheating

If the player guesses a number outside 1 to 100, tell them it is out of range and ask again. An invalid guess should not use up one of their attempts.

Think about: where in the loop should the attempt counter be increased now?

Your guess: 150
Please guess a number between 1 and 100.

Level 4: Play Again

When a game ends, ask Play again? (y/n). If the player types y, start a brand new game with a new secret number. If they type n, print a goodbye message.

Think about: this needs a second loop outside the game. Because the game is already inside play_game(), the outer loop only needs to call the function again. Make play_game() return the number of attempts the player took (or None if they lost); you will need it in Level 6.


Level 5: Difficulty Settings

Before each game, let the player choose a difficulty:

  • Easy: 1 to 10, with 5 attempts
  • Medium: 1 to 50, with 7 attempts
  • Hard: 1 to 100, with 7 attempts

Change play_game() so it takes two parameters, the highest possible number and the number of attempts, e.g. play_game(50, 7). Every message that mentions 100 must now use the parameter instead. Your Level 3 check should use it too.


Level 6: High Scores

Keep a list of the attempts taken in every game the player wins. When they choose to stop playing, print a summary:

Games won: 3
Best score: 4 attempts
Average: 5.3 attempts

Think about: where should the list be created so that it is not reset at the start of every game? What should happen if the player never won a game? (Dividing by len() of an empty list causes a ZeroDivisionError.)


Level 7: Crash-Proof Input

At the moment, typing a word such as fifty crashes the game with a ValueError. Make your game handle this: if the input is not a whole number, print a friendly message and ask again, without using up an attempt.

New idea: the string method .isdigit() returns True if every character in a string is a digit. Check the input before converting it with int(). Make sure the difficulty menu and the play again question cope with unexpected answers too.


Level 8: Turn the Tables (Boss Level)

Write a new function, computer_guesses(), where the roles are reversed. The player thinks of a number between 1 and 100, and the computer has to guess it. After each guess the player types h (too high), l (too low) or c (correct).

Think of a number between 1 and 100.
Is it 50? (h/l/c): h
Is it 25? (h/l/c): l
Is it 37? (h/l/c): c
I got it in 3 guesses!

Think about: the computer should use the binary search strategy described above. Keep two variables, low and high, for the range the number could still be in. Each guess is the middle of that range, (low + high) // 2. If the guess is too high, what is the new high? If it is too low, what is the new low?

For a final twist, detect when the player is cheating. If their answers are impossible (when low becomes greater than high), the computer should call them out.
