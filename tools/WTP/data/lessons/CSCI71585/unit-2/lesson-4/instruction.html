Meaning, Not Appearance

Most of the elements in this lesson change how text looks by default, such as making it bold or italic. But just as with headings, you should choose them for what they mean, not how they look. Appearance can always be changed with CSS; meaning is what browsers, screen readers and search engines rely on.


Important and Stressed Text

  • <strong> marks text that is important, serious or urgent, such as a warning. Browsers display it in bold.
  • <em> marks text with stress emphasis: the word you would stress if you said the sentence aloud. Browsers display it in italics.

Stress emphasis can change the meaning of a sentence:

<p>I <em>never</em> said she deleted the file.</p>
<p>I never said <em>she</em> deleted the file.</p>

The first sentence denies saying anything; the second suggests someone else deleted it.

Bold and Italic Without Extra Meaning

HTML also has <b> and <i>, which display the same as <strong> and <em> but carry different meanings:

  • <b> draws attention to text without making it more important, such as keywords in a summary or product names in a review.
  • <i> marks text in a different voice or mood from the text around it, such as a technical term being introduced, a phrase in another language or a book title.
<p><strong>Warning:</strong> this will delete all of your files.</p>
<p>Computers store data in <i>binary</i>, a number system with only two digits.</p>
💡 Tip: In most cases, <strong> and <em> are the right choice. Ask yourself: "Is this text important, or stressed?" If the answer is no and you still want it to stand out, consider <b> or <i>. If you only want it to look different, use CSS instead.

Other Text-Level Elements

There are many more elements for marking up small pieces of text. These are some of the most useful:

  • <mark> highlights text because it is relevant to the reader right now, like a highlighter pen on revision notes, or search terms in search results. Browsers display it with a yellow background.
  • <code> marks a piece of computer code, such as a command or a function name. Browsers display it in a monospace font.
  • <kbd> marks keyboard input, such as Ctrl + S.
  • <sub> displays subscript text (lowered), used for things like chemical formulas (H2O) and number bases.
  • <sup> displays superscript text (raised), used for things like powers (x2) and ordinal numbers (1st).
  • <small> marks side comments and small print, such as copyright notices and terms and conditions.
<p>Press <kbd>Ctrl</kbd> + <kbd>S</kbd> to save.</p>
<p>Run <code>print("Hello")</code> to test your setup.</p>
<p>10<sup>3</sup> = 1000</p>
ℹ️ Info: <code> is for short pieces of code within a sentence. For a whole block of code, wrap it in both elements: <pre><code>...</code></pre>. The <pre> keeps the line breaks and indentation, and the <code> says that it is code. This is exactly how the code examples in these instructions are written.

Nesting

You have already been nesting elements: putting one element inside another. Every element on your page sits inside <body>, which sits inside <html>, and you have just put <sup> elements inside paragraphs. To talk about how elements relate to each other, developers borrow words from family trees:

  • Parent: the element directly containing another element.
  • Child: an element directly inside another element.
  • Siblings: elements that share the same parent.
  • Ancestors and descendants: elements any number of levels above or below.
<body>
    <h1>Revision Notes</h1>
    <p>This is <strong>important</strong>.</p>
</body>

Here, <h1> and <p> are siblings, and both are children of <body>. The <strong> is a child of <p> and a descendant of <body>. These terms will matter a great deal when you start selecting elements with CSS and JavaScript.


Rule 1: Close in Reverse Order

An element must be closed inside its parent. This means elements always close in the reverse order to how they were opened: the last one opened is the first one closed.

<!-- Correct: em opened last, so it closes first -->
<p>This is <strong>very <em>important</em></strong>.</p>

<!-- Incorrect: the tags overlap -->
<p>This is <strong>very <em>important</strong></em>.</p>

Think of each element as a box: a box can sit inside another box, but two boxes cannot partly overlap.

⚠️ Warning: Overlapping tags often still look correct in the preview, because the browser quietly guesses what you meant. But the browser's guess may not match your intention, and it can cause problems that are very hard to track down once CSS and JavaScript are involved.

Rule 2: Some Elements Cannot Contain Others

Not every element can go inside every other element. As a general rule:

  • Text-level elements, such as <strong>, <em> and <code>, can go inside paragraphs, headings and list items.
  • A paragraph can only contain text and text-level elements. It cannot contain a heading, a list or another paragraph.
  • As you learned in Lesson 3, <ul> and <ol> can only contain <li> elements directly.

If you put a list inside a paragraph, the browser does not show an error. Instead, it closes the paragraph just before the list, which changes the structure of your page without telling you. You will learn more about why these rules exist in Lesson 8.


Nested Lists

A list item can contain another list, which is useful for showing categories and sub-categories. The nested list goes inside an <li>, after that item's text and before its closing tag:

<ul>
    <li>Front-end
        <ul>
            <li>HTML</li>
            <li>CSS</li>
        </ul>
    </li>
    <li>Back-end</li>
</ul>

Notice that the closing </li> for Front-end comes after the nested list. The nested list belongs to that item. You can mix list types too: an <ol> can contain a <ul>, and the other way around.

⚠️ Warning: A common mistake is to put the nested list directly inside the outer <ul>, between two <li> elements. This breaks the rule that only <li> elements can go directly inside a list, even though it may look correct in the preview.
💡 Tip: Indentation is what makes nesting readable. Every time you open an element that contains other elements, indent its contents one level further with Tab. If your indentation is consistent, a missing or misplaced closing tag is much easier to spot.
