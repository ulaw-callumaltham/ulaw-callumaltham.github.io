Tutorial

Images, video and audio make pages far more engaging, but each one also needs some care: a missing description can make an image meaningless to a screen reader user, and a large file can make a page painfully slow to load. In this lesson you will learn how to add media to a page, and how to do it in a way that works for everyone.

The starter code contains a short guide to a day at the coast. As before, complete each Try It section in the editor before moving on.


Images

Images are added with the <img> element. It is a void element, so it has no closing tag; everything it needs is given in attributes:

<img src="images/coast.jpg" alt="Waves breaking on a sandy beach below tall cliffs">
  • src (short for source) is the path to the image file. It works exactly like href in the last lesson: it can be a relative path to a file on the same site, or an absolute URL.
  • alt (short for alternative text) is a text description of the image.

<img> is a text-level element, so it can sit inside a paragraph, alongside text.

Try It

  1. Below the introduction paragraph, add an image with a src of images/coast.jpg, and write your own alt text describing what you can see in it.
  2. Now misspell the file name in src, for example images/cost.jpg. The browser cannot find the file, so it shows a broken image icon with your alt text instead.
  3. Correct the file name.

Writing Good Alt Text

Alt text is read aloud by screen readers, shown when an image fails to load, and used by search engines to understand what an image shows. Good alt text describes the content and purpose of the image in the context of the page:

  • Be specific and concise. alt="Dog" says very little; alt="A golden retriever catching a ball on a beach" says what matters. Aim for a sentence at most.
  • Do not start with "Image of" or "Picture of". Screen readers already announce that it is an image.
  • Consider the context. The same photo of a laptop might need alt="A silver laptop" on a shop page, but alt="A student coding in the library" on a university page.
  • Include any text in the image. If an image contains words, such as a poster, the alt text must include them.
  • Describe the destination for linked images. If an image is inside a link, the alt text is the link text, so it should say where the link goes, such as alt="Home" for a logo that links to the home page.

Some images are purely decorative, such as a background pattern or a divider, and add nothing to the content. For these, use an empty alt attribute, alt="", which tells screen readers to skip the image.

⚠️ Warning: An empty alt (alt="") and a missing alt are not the same. If the alt attribute is missing completely, many screen readers read out the file name instead, such as "IMG underscore 4 0 7 2 dot jpg". Every image must have an alt attribute, even if it is empty.

Width and Height

The width and height attributes give the image's size in pixels. The values are numbers only, with no units:

<img src="images/coast.jpg" alt="..." width="800" height="600">

These attributes let the browser reserve the right amount of space for the image before it has downloaded. Without them, the page is laid out without the image, then everything below it jumps down when it arrives. This is called layout shift, and it is why you sometimes click the wrong thing on a page that is still loading.

💡 Tip: Set width and height to the image's real size, or to smaller values with the same proportions. To display an image at different sizes on different screens, you will use CSS. If an image file is much larger than it will ever be displayed, resize the file itself; shrinking it with attributes still makes the user download the full-size file.

Try It

  1. The coast image is 800 pixels wide and 600 pixels high. Add width and height attributes to display it at half that size.

Image Formats

ℹ️ Info: The four image formats you will use most on the web are:
  • JPEG (.jpg): for photographs. Small files, but no transparency.
  • PNG (.png): for graphics with sharp edges, text or transparent backgrounds. Usually larger files than JPEG for photos.
  • SVG (.svg): for logos and icons. Made of shapes rather than pixels, so they stay sharp at any size.
  • WebP (.webp): a modern format that does both jobs of JPEG and PNG, with smaller files.
⚠️ Warning: Images found online are protected by copyright unless their licence says otherwise. Only use images you have created yourself, have permission to use, or that are released under a licence that allows reuse, such as those on Unsplash, Pexels or Wikimedia Commons. Check the licence, and credit the creator if it asks you to.

Figures and Captions

When an image is a self-contained piece of content with a caption, such as a photo in an article or a diagram in a report, wrap it in a <figure> element, and put the caption in a <figcaption>:

<figure>
    <img src="images/coast.jpg" alt="Waves breaking on a sandy beach below tall cliffs" width="400" height="300">
    <figcaption>The beach is best visited at low tide.</figcaption>
</figure>

The <figcaption> links the caption to the image, so screen readers announce them together.

💡 Tip: The alt text and the caption do different jobs, so they should not repeat each other. The alt text replaces the image for people who cannot see it; the caption adds information for everyone, such as context or a credit.

A <figure> is not only for images. It can also hold a code example, a quotation or a chart, as long as the content makes sense on its own.

Try It

  1. Wrap your image in a <figure> element.
  2. Add a <figcaption> after the image that adds information the alt text does not, such as when to visit or where the photo was taken.
  3. Check that the <figure> is not inside a paragraph. A figure is a block of content in its own right, so it cannot go inside a <p>.

Video

Video is added with the <video> element. Unlike <img>, it has a closing tag:

<video src="media/waves.mp4" controls width="400" height="225">
    Your browser does not support video. <a href="media/waves.mp4">Download the video</a> instead.
</video>
  • src is the path to the video file.
  • controls is a Boolean attribute that shows the play, pause, volume and full-screen buttons. Without it, users have no way to play the video.
  • width and height reserve space, as with images.
  • The content between the tags is a fallback: it is only shown by browsers that cannot play video at all.

Other useful attributes are:

  • poster: the path to an image shown before the video starts playing.
  • muted: starts the video with the sound off.
  • loop: restarts the video when it ends.
  • autoplay: starts playing as soon as the page loads. Most browsers only allow this if the video is also muted.
⚠️ Warning: Avoid autoplay wherever possible. Unexpected movement and sound can be distracting or distressing for some users, uses up mobile data, and can drown out a screen reader. Let users choose when to play media.
ℹ️ Info: To be fully accessible, videos with speech need captions. These are written in a separate text file and added with a <track> element inside the <video>. You will cover this in the accessibility unit later in the module.

Try It

  1. Under the Watch the Waves heading, add a video with a src of media/waves.mp4, displayed at 400 by 225 pixels.
  2. Make sure users can play it, and include a fallback message with a download link.
  3. Play the video in the preview.

Audio

Audio works in exactly the same way, using the <audio> element. Since there is nothing to see, it has no width, height or poster, but controls is even more important: without it, the audio player is completely invisible.

<audio src="media/waves.mp3" controls>
    Your browser does not support audio. <a href="media/waves.mp3">Download the audio</a> instead.
</audio>

Try It

  1. Under the Listen to the Sea heading, add an audio player with a src of media/waves.mp3, with controls and a fallback message.

ℹ️ Info: You may also see the <iframe> element, which displays one web page inside another. It is how YouTube videos and Google Maps are embedded in other websites, and the services provide the code for you to copy. In fact, the preview you have been using is an <iframe> itself.

Check Your Page

Your figure should be structured like this, with your own alt text and caption:

<figure>
    <img src="images/coast.jpg" alt="Your description here" width="400" height="300">
    <figcaption>Your caption here.</figcaption>
</figure>

Also check that:

  • Your alt text describes the image without starting with "Image of", and your caption does not repeat it.
  • The video and audio players both have controls and a fallback message.
  • Nothing plays automatically when the page loads.
